开发集五折结果（未使用测试集），按 AP 排序：

| 模型 | 选定配置 | AP | ROC-AUC | Brier |
|---|---|---|---|---|
| Random Forest | 200 棵树，max_depth = 10 | 0.557 ± 0.006 | 0.781 | 0.135 |
| Logistic Regression | C = 1，PAY one-hot | 0.544 ± 0.008 | 0.769 | 0.137 |
| AdaBoost | 100 个树桩，learning rate = 0.1 | 0.536 ± 0.004 | 0.769 | 0.139 |
| KNN | k = 61 | 0.512 ± 0.006 | 0.752 | 0.141 |
| Decision Tree | max_depth = 5 | 0.511 ± 0.008 | 0.756 | 0.138 |
| Gaussian NB | 默认配置 | 0.487 ± 0.015 | 0.734 | 0.286 |
| 常数基准（输出训练违约率） | — | 0.221 | 0.500 | 0.172 |

参数网格都在实验前写定（[登记表](../src/models/registry.py)）。几点已经能看到的现象，供后续分析参考：

- 前三名的 AP 差距（0.557、0.544、0.536）只有一到两个折间标准差，能否区分要看测试集 bootstrap 区间。
- Logistic 的概率接近校准，折外选出的阈值与理论值 1/(1+r) 很接近。
- Gaussian NB 的排序能力尚可，但 Brier 高于常数基准，即它的概率还不如直接报基础违约率。
- KNN 选中的是网格中最大的 k = 61，AP 随 k 增大一直上升，最优值可能在网格之外。报告中照实说明；若要扩展网格，只能在冻结前做一次并写明理由。
- 随机森林额外固定了 `min_samples_leaf = 5`，方法部分需写明。

Gaussian NB 只用一套默认配置：PAY 改用 one-hot 时 AP 的变化（0.005）小于折间标准差，不足以作为选择依据。

## 4. 新增分析的做法

三项分析都读 `results/predictions/oof_<模型名>.csv`，不需要重新训练。

### 4.1 成本比敏感性

$$C_r(t) = r\cdot FN(t) + FP(t),\qquad r\in\{1,2,3,5,10\}.$$

对每个模型、每个 $r$，用 `select_threshold` 在折外预测上选 $t^*_{m,r}$，写入冻结清单，测试时原样使用。默认阈值 0.5 作为对照一并报告，这是 Proposal 承诺的比较。

| 产出 | 内容 | 回答的问题 |
|---|---|---|
| 阈值表 | 模型 × 成本比 的 $t^*$ | 阈值如何随 $r$ 移动 |
| 成本表 | 模型 × 成本比 的测试集每客户成本，每列标出最低者 | 最优模型是否随 $r$ 改变 |
| 图 | 横轴 $r$、纵轴每客户成本，六条线加两条参照线 | 排名在哪里交叉 |

**参照策略**。设违约率为 π，"全不报警"的每客户成本是 $r\pi$，"全部报警"是 $1-\pi$，两者在 $r=(1-\pi)/\pi\approx3.5$ 处相等。所以 $r\le3$ 时模型要打败的是"全不报警"，$r\ge5$ 时是"全部报警"。成本表加一行较优的参照策略（`trivial_costs`），并报告模型相对它的成本下降百分比；原始成本数值随 $r$ 变大，不同列之间不能直接比较。

**理论阈值**。概率校准时，成本最小的阈值是 $1/(1+r)$，即 0.50、0.33、0.25、0.17、0.09。把选出的 $t^*$ 与它并列，偏离程度本身就是校准的证据。

**表述**。5:1 写作 *pre-specified primary scenario*，其余写作 *sensitivity scenarios*；任何一档都不称为台湾持卡人的真实成本。

### 4.2 校准与 Brier

$$\text{Brier}=\frac1N\sum_i(\hat p_i-y_i)^2.$$

- 六个模型都报告，折外和测试各一列（`ranking_metrics` 已返回）。
- 参照值是常数基准的 Brier，约 0.172。同时报 Brier skill score $=1-\text{Brier}/\text{Brier}_{\text{ref}}$，小于 0 表示不如基础违约率。
- 校准曲线：按预测概率等频分 10 箱，横轴平均预测概率，纵轴实际违约率，六个模型画在一张图上（`calibration_table`）。

### 4.3 为什么 AP 最高不等于成本最低

| 机制 | 说明 | 证据 |
|---|---|---|
| 整体与局部 | AP 汇总整条 PR 曲线，$C_r$ 只取决于一个操作点 | AP 排名与各成本比下成本排名并列的名次表 |
| 曲线交叉 | ROC 平面上等成本线的斜率为 $\dfrac{1-\pi}{r\pi}\approx\dfrac{3.52}{r}$，最优点是曲线与该斜率相切处；两条 ROC 曲线交叉时，不同 $r$ 下赢家不同 | 前两三名模型的 ROC 曲线加等成本线 |
| 阈值迁移误差 | $t^*$ 在折外预测上估计，用到测试集上不一定仍是最优；分数粗糙或校准差的模型更容易吃亏 | 冻结阈值的测试成本与测试集事后最优成本之差 |

事后最优阈值只作诊断，报告中写明它没有用于任何选择。

**差距是否只是噪声**：对测试集做成对分层 bootstrap（2000 次），给出 AP 最优模型与成本最优模型之间 ΔAP 和 Δ成本的 95% 区间。区间跨 0 就写"在本数据上无法区分"。它只反映测试样本的抽样波动，训练波动用五折标准差说明。

若时间不够，迁移误差和 bootstrap 只进报告、不进 PPT；成本表、校准曲线、名次表三样不能省。

### 4.4 特征解释

Proposal 承诺讨论 Logistic 系数和树模型的特征重要性。做法：在完整开发集上拟合冻结的配置后提取，不使用测试集。

- Logistic：标准化后的系数，注意 one-hot 列的系数是相对于被省略或其他类别的。
- 随机森林、AdaBoost、决策树：sklearn 自带的基于不纯度的重要性；不同模型的重要性量纲不同，不做跨模型的数值比较。
- 解读一律写成"预测上的关联"，不写因果，LIMIT_BAL 的反向因果问题见 7.2。

### 7.2 Discussion：事实 → 推断 → 建议

逐个检查两个箭头，写法是承认问题、说明影响多大、说明做了什么检验或还需要什么证据。

**6.1 What the test set shows（事实）**
只陈述数字及其不确定性：各模型测试 AP、ROC-AUC、Brier；各成本比下的冻结阈值与成本；bootstrap 区间。这一小节不出现 "better" 和 "should"。

**6.2 From metrics to "which model is better"（第一个箭头）**
- 指标不同：AP 和 AUC 衡量整条曲线上的排序，成本只看一个点。放 4.3 的三个机制和名次表。
- 噪声：前几名的差距是否超出 bootstrap 区间和五折标准差；超不出就写无法区分，并说明此时可按简单、可解释来选。

**6.3 From "better model" to "what a lender should do"（第二个箭头）**
- 成本比的来源：5:1 出自 German Credit，代表不了台湾持卡人。敏感性分析说明建议在多大的成本比范围内保持不变。
- 校准：若银行要把分数当违约概率用，Brier 和校准曲线说明哪些模型的分数不能这样用。
- 建议写成条件句：*if the cost ratio lies between a and b, use model X at threshold t*。成本比很大时"全部报警"已接近最优，问题就不再是选哪个分类器，而是银行有多少复核能力。
- 解释性：系数和特征重要性只说明预测上的关联。例如 LIMIT_BAL 高与违约少相关，很可能是银行本来就给信用好的人更高额度，不能读成"提额能降低违约"。

**6.4 Limitations，分轻重**

| 级别 | 问题 | 影响 | 已做的检验或所需证据 |
|---|---|---|---|
| 重 | 真实成本比未知 | 最优阈值乃至最优模型随 $r$ 变化 | 已做五档敏感性；需要银行的损失率与客户流失数据 |
| 重 | 2005 年、台湾、单一银行；随机划分而非按时间划分 | 不能外推到今天或其他市场 | 需要跨期样本做 out-of-time 验证 |
| 中 | 样本只含已获批的持卡人 | 不适用于审批阶段的申请人 | 需要被拒申请人的数据 |
| 中 | 参数与阈值由交叉验证选出，存在选择乐观；阈值迁移有误差 | 测试成本可能高于折外成本 | 报告折外与测试的差、迁移误差 |
| 中 | 部分模型校准差 | 分数不能当概率解读 | 报告 Brier 与校准曲线 |
| 轻 | 参数网格小；Gaussian NB 的假设不成立；PAY 的 -2 和 0 无官方定义；不同模型的重要性不可直接比较 | 个别模型可能未到最优，不影响主要结论 | 网格事先写定并记录 |
